# Revamp — agent suggestions (out-of-scope findings; one bullet per finding, prefixed with the step that noticed it)

- A1: `package-lock.json` had to be regenerated from scratch (npm 11.5.1 arborist crash: `Cannot read properties of null (reading 'edgesOut')`; no `@rolldown/binding-*` entries). Transitive deps moved within their semver ranges (e.g. `next` 14.2.32→14.2.35, `next-auth` beta.30→beta.32, `@vercel/analytics` 1.5.0→1.6.1). Worth a quick smoke test of sign-in + Stripe routes on `master`'s deploy path before cut-over, or diff the lockfile if anything regresses.
- A1: vitest is pinned to `^3` because npm 11.5.1 cannot resolve vitest 4 (arborist crash on its circular optional peers; `--legacy-peer-deps` works around it) and vitest 5 needs rolldown platform bindings that npm did not install. Revisit after an npm upgrade (`npm i -g npm@latest`) — no code changes expected.
- A1: 32 `react-hooks/rules-of-hooks` warnings, all in `components/Editor/Builder/BuilderMain.tsx` (hooks after `if (!grid) return null`). B2 fixes; then flip the rule to `error`.
- A1: 3 `@next/next/no-img-element` warnings (`app/editor/page.tsx`, `components/Editor/UserMenu.tsx`, `components/ProgressPreviewModal.tsx`). With `images.unoptimized` and a static export, `<img>` is the right tag — consider turning the rule off in E3 rather than migrating to `next/image`.
- A1: `lib/dice/svg-renderer.ts` re-derives the dot layout inline instead of calling `getDotPositions` (plan already dedupes this in A3 `core/dice/svg.ts`).
- A2: `public/demo-portrait.jpg` is a 329-byte text placeholder ("Placeholder for Mona Lisa Image"), not a JPEG; nothing in `app/ components/ lib/` references it. Delete it in the E3 sweep (fixtures use `public/images/monalisa.webp`).
- A2: root `tsconfig.json` has no `target`, so `tsc --noEmit` type-checks against ES5 semantics (`for…of` over a typed array is TS2802 even though `lib` is esnext). Consider `target: "es2022"` in E3; Next ignores it for bundling.
- A2: `lib/dice/generator.ts` `generateGrayscalePreview` duplicates the whole gamma/contrast/sharpen pipeline for the tune-step preview; B1's `useDicePipeline` should derive the preview from the core's downsampled gray image instead of re-running it in a canvas.
- A3: the plan's D1 uses `npm:zod@3` for the Deno edge functions while core now depends on `zod@^4` (the version already in the tree). Use `npm:zod@4` in `deno.json` so the two runtimes share one API (and `document.schema.ts` could be mirrored verbatim if ever needed server-side).
- A3: `ProgressPreviewModal` sizes its raster as `min(long*10, 1080)` while `useDiceGeneration` uses a fixed 1080 long side; both are `rasterSize(cols, rows, longSide)` now — B1 should pick one long-side rule for `lib/image/rasterize.ts` rather than keeping two.
- A3: the old `lib/subscription.ts` `canManage` excluded lifetime users and `creator_pass` status; the new `canManageBilling` is simply "has a Stripe customer" (plan decision). D2's Account page should tolerate a lifetime user with a customer opening a portal that lists no subscription.
- A3: legacy Prisma users with `subscriptionStatus = 'creator_pass'` have no equivalent status in the new model; F1 must map them to `plan = 'creator'`, `plan_expires_at = subscriptionExpiresAt` (and any `isPro && planType='explorer'` rows should be inspected by hand — the old predicates disagreed).
- A3: root `tsconfig.json`'s missing `target` bit again (`[...str.matchAll()]` is TS2802 under `tsc --noEmit` although it runs fine) — tests use `Array.from` as a workaround; adding `target: "es2022"` in E3 removes the papercut.
- A3: `next build` logs `[USER_SUBSCRIPTION_GET] Dynamic server usage` from `app/api/user/subscription` (Next probing the route for static rendering). Harmless noise that disappears with `app/api/**` in E1.
- B1: the old `cropper.getCanvas({ width: 2048 })` always resampled the crop to 2048 px wide (upscaling small crops); `cropToPixels` never upscales (`fitScale` ≤ 1), so a crop under 2048 px is now sampled at native resolution. More faithful, but the tune preview for tiny images can look slightly different from `master`.
- B1: `app/api/user/commission-interest/route.ts` is dead now that `CommissionModal` is gone (nothing calls it); E1 deletes `app/api/**` anyway. `app/api/projects/route.ts` still accepts a `croppedImage` body field and `ProjectSelectionModal`'s `Project` DTO still declares `croppedImage` (Prisma column) — both go with C3.
- B1: `TunerMain` shows its spinner on `cropParams`/`diceParams` identity changes (heuristic); B3's `isGenerating` in the derived store should replace it.
- B1: `react-hooks/exhaustive-deps` warns on `runIdRef.current++` in `useDiceGeneration`'s cleanup (false positive: it is a counter, not a DOM ref); same pattern as before. `CropperMain` still imports unused `Coordinates`/`AspectRatio` (pre-existing warnings) — E3 sweep.
- B1: `renderProgressSvg` embeds `isCompleted` (current die not counted), so the ProgressPreviewModal off-by-one the plan assigns to B2 is already fixed; B2 only needs to keep it.
- B1: `lib/image/*` canvas paths (`drawRegion`, `rasterizeSvg`) have no unit tests because vitest runs in the node environment; if a DOM environment is ever added (`jsdom` + `canvas`), `cropToPixels` on a 2×2 synthetic image with rotation 90 would be the first test to write.
- B2: `totalDice > 0 ? (currentIndex / totalDice) * 100 : 0` is written three times (`BuilderPanel` L204, `MobileBuildControls` L35, `ResetProgressModal` L22, the last one reading the store directly instead of `useBuildNavigation`). B3's derived store (or the navigation hook) should expose one `progressPercent`.
- B2: `useBuildNavigation` gates on `session.user.planType` while `BuilderLimitToast` (same folder) gates on `session.user.isPro` — the two "is pro" predicates the plan's Context mentions, side by side. C2's `useGate`/`useEntitlements` should replace both; until then the toast can show for a user the navigation treats as unlimited (or vice versa).
- B2: `useBuildNavigation` returned `hasUnlimitedDice` and `diceLimit` ("Expose for UI") but nothing consumed them; dropped in the port. `diceLimit` was the last `Infinity` in the editor.
- B2: old `navigateNext` ran `enforceLimit(currentIndex + 1)` before checking bounds, so at the very last die of a ≤ 5-row grid an explorer would get the limit modal instead of a no-op; `nextPosition` returns `null` there so it is a plain no-op now. Unreachable with the real slider range (numRows ≥ 20) and `canNavigate.next` disables the control anyway.
- B2: `useElementSize` (ResizeObserver → `{ width, height } | null`) is generic; if B5's `useMediaQuery` lands next to it, consider one `lib/` hook file (or `usehooks-ts`'s `useResizeObserver`) rather than a second copy.
- B2: `vitest.config.ts` does not include `components/**/*.test.ts`; nothing needed it this step (the new files are hooks/JSX around tested core functions), and B5 moves the folder under `features/` which is included — no change made.
